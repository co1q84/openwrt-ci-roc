# J4125 Firmware Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task by task. Design and execution are already authorized; do not request design approval again.

**Goal:** Build and publish a traceable x86/64 firmware that retains the current router's functions and provides a checked, manually confirmed upgrade entry.

**Architecture:** Keep the Taiyi workflow and common package configuration intact. Each x86 build resolves the newest system, feed and plugin heads, then freezes their exact commits for that run's source preparation, validation and release packaging. Ship a standalone router updater that can also run from `/tmp` on the old firmware, uses private device-side backups and refuses unsafe upgrades. No plugin version is permanently pinned.

**Tech Stack:** GitHub Actions, ImmortalWrt, Python standard library, POSIX shell, jq, sysupgrade.

**Spec:** User-approved `.local/router-audit/adaptation-plan.md`; private audit evidence remains local. Public constraints are restated below.

## Global Constraints

- x86/64, UEFI, squashfs, boot 64 MiB, root 960 MiB; igc, USB storage, PPPoE, LuCI and SSH required.
- Preserve restored hostname, theme, timezone, network, SSH port, disabled IPv6 and disabled services. Never embed private configuration or identities.
- Retain installed applications and relevant existing package features. Report renamed or unavailable packages; fail if required selections disappear from defconfig or manifest.
- Record exact source/feed commits, final config, package manifest, checksums and EFI image metadata. Stop on failures.
- No runtime configuration writes, package installation, reboot or flashing on the live router in this session. `sysupgrade -T` and image comparison are allowed.
- Upgrade is interactive: correct hardware/layout, SHA256, backup validation and user-held backup must precede confirmation. Never force flashing.
- Keep OpenClash user configuration but do not restore old executable cores over new build artifacts.

## Review Focus

1. Missing or disabled dependencies silently remove a selected application: reject the resolved configuration and image manifest.
2. A different device, filesystem or partition layout appears: block before any upgrade command.
3. An interrupted publication or changed image/checksum appears: use a complete immutable release and reject hash mismatch.
4. Existing configuration or old executable cores collide with defaults: preserve device settings and exclude cores from the migration archive.
5. Backup/download/check failure or absent interactive confirmation: return failure without calling a flashing command.
